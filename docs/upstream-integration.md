## Commands
In each app's own session run context, keyword-plan, learning-review. Configure loop.apps[ID].aso.keywords and storefronts. The keyword plan schedules one observation per configured phrase and country; use keyword-check with appId, keyword, country in JSON in imports/ID. Each call makes one public iTunes search. Rank is the order from that API, not native App Store search rank. Null means absent from the returned results, not zero. Rate limits and failed requests do not record rank. Repeated calls must obey cooldown. No unattended schedule is installed.

Use health-record with appId, start/end (seven complete days), source, scope, metrics and optional incidents (signature, os, occurrences, evidence) and currency for proceeds. Reports must be verified from authorized exports; weekly metrics still require verified report exports. The separate health-scan command fetches recent TestFlight crash/feedback records and latest build diagnostic signatures via the documented read-only ASC CLI. Counts are limited samples, not total crash counts. It omits raw comments, emails and logs; unavailable or unexpected responses stay unavailable. Compare adjacent weeks only with matching scope/source/currency. Suggested incidents are evidence for review; operator must independently verify and use observe/handoff with approved acceptance, not automatically file GitHub issues.

Before a queued feature/promotion, forecast records appId, taskId, metric (downloads or the predeclared feature metric), expected, rationale, failureCondition. It is immutable for the task. After advance records the actual result, learning-review reports error and flags stale or overlapping skill lessons. New lesson revisions require same-app closed task evidence. No model retraining or automated causal claim.

## Agent-authored video (OpenDesign + HyperFrames)
The agent reads the pinned OpenDesign `design-brief`, `motion-design` and `video-hyperframes` skills and writes a storyboard (`schema --name storyboard`). The runner validates provenance, claims with evidence, WCAG AA theme contrast, layouts, timing, captions and licensed audio, then composes a HyperFrames project following its format reference: media is timed at the root rather than nested in timed scenes, entrances use `fromTo`, and the timeline is registered as `promo`. `video --storyboard` runs `npx hyperframes@0.9.95 check --json` as a gate. Errors return `needs-revision` with selectors and nothing is rendered. A passing check renders at 30 fps; FFprobe verifies size, duration and audio, and one review frame per scene is written to `review/`. Telemetry is disabled. The legacy 12-second brief template remains.

## Remaining boundaries
Automated native App Store rank retrieval, full weekly Analytics report ingestion, full ASO Studio graphical editor and In-App Events, and direct authorized Apple writes are not supplied by these ports. A local deterministic screenshot renderer and PPO evidence workflow are included, not the full ASO Studio AI editor. Existing store-draft, creative, approval and manual browser steps remain. Separate profiles and OS accounts are needed for actual credential security; app-scoped SQLite is logical isolation. Real Apple and social accounts and installed desktop sessions must be tested by the owner. CI uses fixtures and does not simulate a real successful campaign.

## Optional explicit account routing
Set top-level appAccounts to a map keyed by exact App Store ID, each with bundleId and a distinct ascProfile; optional vendor, adsProfile, adsAccounts. When nonempty, app actions require configured IDs, live scan/feedback verifies exact ID and bundle ID using its own named ASC profile. Browser inventory/store fallback and ambient report-account fallback are disabled in this mode. Run live scan/cycle per app and portfolio for summaries. This prevents accidental profile switching in the runner, not OS-level credential theft; the owner must create genuinely limited account keys, profiles and separate OS/browser sessions where required. Existing shared-profile configurations remain supported.

Use rank-import with appId, keyword, country, observedOn, evidence, complete:true, export (verified native search response). Source must be a real authorized export; the parser detects schema drift. Never compare native ordering with iTunes API. keyword-plan returns distinct histories and competitor overlap per storefront and source.

## Local screenshot and PPO
Screenshot: `screenshot --app ID --input screenshot.json --screenshot approved.png` uses a real approved capture in assets/ID, input appId, verifiedVersion, listingSha, locale, device (iphone-large, iphone-medium, iphone-6.5, ipad-13), style (midnight, paper, orchid), headline, subtitle, captureEvidence, approvedCapture:true. Google Chrome must be installed; owner may set creative.chrome to its exact executable. PNG is checked for exact dimensions and opaque format; visually review the draft. Supported portrait presets are sourced from https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/. No external AI calls. PPO plan/result store version, locale, control, 1–3 treatments, threshold, complete Apple-reported results and approval receipt. Review before any application to Apple. It is a local plan/evidence tool, not a direct Apple experiment creation API.

For obsolete or contradicted learned rules use lesson-retire with appId, domain, key, expectedRevision, reason, taskIds (closed outcomes of that app). This appends a retirement revision and removes it from active recommendations without deleting the evidence. A later supported lesson can supersede it.
